# SmartyNote version history

Product display format: `00.00.000` (major, design/feature milestone, patch).
Original GitHub Actions run numbers remain immutable; failed and unpublished runs
are recorded but are not releases. Patches follow the original run number within
each milestone, so gaps in published packages are expected.

| 00.05.000 | 55 | ShortCats and event handling |
| 00.06.000 | 57 | Weather and availability |
| 00.07.000 | 62 | Branding and Rocky artwork |
| 00.08.000 | 68 | Last six-section release |
| 00.09.000 | 69 | Start of four-quadrant branch; this first attempt failed CI |
| 01.00.000 | TBD | Reserved for accepted public release |

The mapping is a product-version convention, not a certification of device
testing. Historical images explicitly show 62 and 68; other historical
device-test identifications require confirmation.

Historical releases retain their original `dev-build-N` tags and package bytes
for backward-compatible downloads, but are titled with the new product version;
matching `v00.00.000` Git tag aliases point at the identical historical objects.
Previously installed packages are not retroactively modified. New packages use
the padded product version in the dashboard and plugin metadata, and the
original run number as the monotonically increasing plugin version code.
New release tags use the padded product version. npm versions are unpadded
because the SemVer standard disallows leading zeros.
